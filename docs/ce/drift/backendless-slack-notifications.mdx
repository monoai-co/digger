---
title: "Backendless: Slack Notifications"
description: "Send backendless drift detection results to Slack from scheduled GitHub Actions runs"
---

In Backendless mode, drift detection runs in GitHub Actions and sends notifications directly from the workflow run.

## Configure Slack webhook input

Pass `drift-detection-slack-notification-url` to the action:

```yml
name: Drift Detection

on:
  workflow_dispatch:
  # schedule:
  #   - cron: "0 0 * * *"

jobs:
  detect-drift:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0 # required for last change attribution
      - name: digger drift detection
        uses: diggerhq/digger@vLatest
        with:
          mode: drift-detection
          no-backend: true
          drift-detection-slack-notification-url: ${{ secrets.SLACK_WEBHOOK_URL }}
        env:
          GITHUB_CONTEXT: ${{ toJson(github) }}
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

## Last change attribution

When drift is detected, the notification includes who last changed the project's directory, taken from `git log` on the runner:

> :bust_in_silhouette: **Last change by:** Jane Doe (`abc1234`, 3 days ago)

This requires full git history in the checkout — set `fetch-depth: 0` on `actions/checkout` as shown above. On a shallow clone the attribution line is skipped and the notification is sent without it.
